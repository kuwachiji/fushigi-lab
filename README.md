# ふしぎな実験室

すな・みず・ひ・あぶら・こおり・たね を画面にかいて、ものの性質をたしかめる小学生向けの理科教材です。
砂は落ちて山になり、水は広がって水平になり、油は水に浮き、火は油や木に燃え移り、氷は火でとけ、たねは水で育ちます。

同時に、**学習プラットフォームが発行するライセンスで無料版と有料版を出し分ける**教材のデモになっています。
教材は別ドメイン（GitHub Pages）に置かれ、ブラウザから直接ライセンス API を呼びます。

- デモ: https://kuwachiji.github.io/fushigi-lab/
- ビルド不要。素の HTML / CSS / JavaScript だけで、外部ライブラリは使っていません。

## 無料版と有料版のちがい

| | 無料版 (`free`) | 有料版 (`premium`) |
|---|---|---|
| 材料 | すな・みず・かべ・けしゴム | すべて（あぶら・ひ・き・こおり・たね を追加） |
| ふでの太さ | ふつう のみ | ほそい・ふつう・ふとい |
| とめる・コマ送り | × | ○ |
| ミッション | 2 つ | 8 つ |
| かんさつノート | × | ○（ブラウザに保存） |
| 写真をとる | × | ○ |
| しゅうりょうしょう | × | 全ミッション達成で表示 |

ライセンスがないときは「見るだけモード」になり、砂と水が自動で降り続けるデモだけが見られます。

## ライセンス連携のしくみ

### 1. 教材の開き方

学習プラットフォームは、教材の URL にクエリ `token` を付けて開きます。

```
https://kuwachiji.github.io/fushigi-lab/?token=<トークン>
```

教材は受け取ったトークンを `sessionStorage` に保存し、`history.replaceState` で URL から消します。
ライセンスサーバーの URL は `app.js` 先頭の `LICENSE_API` に持ち、URL では受け取りません。
`token` が無いときは「見るだけモード」になります。

### 2. ライセンスの取得

教材は次の API をブラウザから直接呼びます。カスタムヘッダや Cookie は付けない「単純リクエスト」なので、preflight（OPTIONS）は発生しません。

```
GET {api}/api/license/?token=<トークン>
```

応答は `{"license": "<値>"}` です。値の意味と、この教材での扱いは次のとおりです。

| `license` の値 | HTTP | 意味 | この教材の表示 |
|---|---|---|---|
| `free` | 200 | この教材の無料ライセンス | 無料版 |
| `premium` | 200 | この教材の有料ライセンス | 有料版 |
| 上記以外の文字列 | 200 | この教材が知らない種類 | 無料版相当で動き、警告を表示 |
| `no` | 200 / 400 / 401 | ライセンス未登録、トークン無し、署名不一致 など | 見るだけモード |
| `expired` | 401 | トークンが無効化された | 見るだけモード（開き直しを案内） |
| `lapsed` | 200 | ライセンスの期間が終了した | 見るだけモード（期間終了を案内） |
| （fetch が失敗） | – | CORS 不許可、接続先の誤り、タイムアウト（5 秒） | 見るだけモード（原因候補を案内） |

`license` の値は製品ごとに自由に決められるため、この教材は `free` / `premium` という独自の値を使っています。
対応表は `app.js` 先頭の `PLANS` にまとめてあり、種類を増やすときはそこに足します。

### 3. ライセンスサーバー側に必要な設定

- この教材のオリジン `https://kuwachiji.github.io` を、製品の許可オリジンとして登録してください。
  許可されていないオリジンからの呼び出しには `Access-Control-Allow-Origin` が付かず、ブラウザが応答を読めません。
- 製品のライセンス種別として `free` または `premium` を登録してください。

## ローカルで動かす

```bash
python3 -m http.server 5500
```

`http://localhost:5500/` を開きます。`file://` で開くと Origin が `null` になり、CORS を通せないので使えません。

### テスト

シミュレーション本体（`sim.js`）のふるまいは Node のテストで確認できます。

```bash
node --test
```

## ハマりどころ

- **ローカルのライセンスサーバーで確認するとき**: `app.js` 先頭の `LICENSE_API` を一時的に書き換えてください（コミットしないこと）。
- **CORS で失敗すると理由が分からない**: ブラウザは CORS 拒否の詳細を JavaScript に渡しません。画面には「確認できません」としか出ないので、DevTools の Network / Console を見てください（Console に呼び出した URL を警告として出しています）。
- **カスタムヘッダを付けない**: `Authorization` などを付けると preflight が必要になり、ライセンス API はそれに応答しません。トークンはクエリで渡します。
- **`file://` では動かない**: 上記のとおり Origin が `null` になります。
